1三條鐵則

  1. 所有變更都走 PR，base 一律打到 develop，不直推。
  2. CI 紅燈不能 merge，但容許自己 merge 自己的 PR。
  3. 動到 schema / env / docker-compose 三者之一，PR 留言 ping 一個隊友再 merge。

2分支模型

分支用途誰能 push
main可部署版本，每個 milestone tag 一次僅 PR (from develop)
develop整合分支，所有 feature 合進這裡僅 PR (from feature/*)
feature/*個人開發新功能個人，merge 後刪除

3分支命名

備註：以下為建議格式，不強求一致。 重點是「看分支名能猜到是誰、在做什麼」，自己順手即可。 

# 建議格式：<type>/<owner>-<short-desc>
feature/be1-auth-login
feature/be2-problem-crud
feature/fe-problem-list
fix/be3-health-timeout
  • type：feature / fix / chore / docs
  • owner：fe / be1 / be2 / be3
  • desc：英文小寫 kebab-case，3–6 個詞

4日常流程（6 步）

# 1. 從最新 develop 開新分支
git switch develop && git pull --ff-only
git switch -c feature/be1-auth-login

# 2. 開發 → commit → push（自己 branch 上隨意，可多次 push）
git add -A && git commit -m "feat: add login route"
git push -u origin feature/be1-auth-login

# 3. 開 PR 前：rebase 最新 develop（重要）
git fetch origin
git rebase origin/develop
#   ← 衝突就在這裡解，git add . && git rebase --continue
git push --force-with-lease

# 4. 開 PR 到 develop
gh pr create --base develop --fill

# 5. 等 CI 全綠（紅燈不能 merge）

# 6. Squash & Merge → 自動刪 branch
gh pr merge --squash --delete-branch

為什麼要在第 3 步先 rebase？

  • CI 跑的是「合進 develop 後的實際狀態」，先 rebase 才會抓到隱藏衝突
  • 衝突自己解比 merge 後再修乾淨
  • PR 開了但 develop 又被別人推新 commit 時，同樣再跑一次第 3 步
  • 平時 commit/push 自己 branch 不需要 rebase，只有「要開 PR / 已開 PR 但 out-of-date」才做

5PR 規則

  • Base 必選 develop，不要打到 main
  • 標題用英文動詞開頭：Add JWT login route、Fix health timeout
  • Squash & Merge（壓成一個 commit 進 develop）
  • 自己 merge 自己的 PR 前，切到 Files changed 重看一次
  • 動到下面三類檔案，留言 ping 一個人再 merge：
    • backend/src/db/schema.ts 或新增 migration
    • .env.example / env.ts
    • docker-compose.yml / Dockerfile

7Commit message 風格

格式不限制，但建議加 type prefix（feat: / fix: / chore: ...）。 review 時掃一眼就知道這 commit 的性質。 

# ✅ 推薦（Conventional Commits 風格）
feat: add login route
fix: health check ipv6 timeout
chore: bump fastify to 4.28
docs: update README setup steps
refactor: extract jwt verifier
test: add login route happy path

# ✅ 也可接受（簡短一行不加 prefix）
init
add login route
fix health timeout

# ❌ 避免：多段落 body 描述背景
chore: scaffold M1 skeleton

This commit adds the initial Docker
scaffolding including frontend...
prefix用途
feat:新功能
fix:bug 修復
chore:build / 套件 / 設定 / 雜項
docs:文件變更
refactor:不改行為的重構
test:新增 / 改動測試
style:格式 / lint，不改邏輯

8遇到衝突

# 在自己的 feature branch 上 rebase develop（不是 merge）
git fetch origin
git rebase origin/develop

# 修衝突 → git add → git rebase --continue
git push --force-with-lease

別人已 merge 進 develop 後，自己每天開工先 rebase origin/develop，避免衝突累積。
